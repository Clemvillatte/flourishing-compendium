# Enrichment task board

Any agent starting on this repository: read `docs/ENRICHMENT-HANDOFF.md` first, then claim work here.

## How to claim

1. Find the first band below with status OPEN (bands are slices of `docs/enrichment/queue-concepts.json`, highest graph degree first).
2. Edit this table: set status to `claimed`, put your agent name and the date. Commit and push (`scripts/enrich_save.sh "taskboard: claim band w1b"`).
3. If the push is rejected after rebase, someone claimed first: pull, re-read the board, take the next OPEN band.
4. When a band is finished, set status to `done` and move on to the next OPEN band (or ask the lead for fresh bands).

## Rules for parallel agents (read before editing anything)

1. **File ownership.** You only edit: concept files whose ids are inside your band, plus files under `docs/enrichment/` whose names start with your prefix (`batches/w1b-*.json`, `proposals/w1b.json`). Never touch another band's concept files, another band's batch/proposal files, `progress.json`, or the queue files.
2. **progress.json** is merged from batch logs by the lead only. Record your finished concepts in your own batch files; the skip-check is your batch file plus `progress.json`.
3. **enrich_apply.py** (cross-link application) is run by the lead only, because it edits other bands' entries. You write proposals in `proposals/<your-prefix>.json`; the lead applies them after pulling. Do not run apply yourself.
4. **Queue files** (`queue-*.json`) are regenerated by the lead only. You may run `enrich_stats.py --show N` to look, but discard the queue-file rewrite before saving: `git checkout -- docs/enrichment/queue-concepts.json`.
5. **Save after every finished concept**: `scripts/enrich_save.sh "enrich: <concept> (<band>)"`. It fails loudly if the push does not land. If it reports a rebase conflict, resolve it in your own files only.
6. **enrich_validate.py** compares against git HEAD: run it after every concept, fix every ERR before moving on. `scripts/build.py` must still succeed before you mark a band done.
7. Quality bar, voice and research rules are in `docs/enrichment/PROTOCOL.md` (binding). Exemplars: `docs/enrichment/EXEMPLARS.md`. Zero hallucination: every fact from a source you actually opened.
8. A second account/agent working from a different checkout: `git pull` before starting, and pull-rebase (the save script does this) keeps you in sync. If you and another agent somehow collide on a file, the board claim in this table is the tiebreaker: the claimer keeps the file.
