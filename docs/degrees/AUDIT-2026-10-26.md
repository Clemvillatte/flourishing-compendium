# Degrees audit — 2026-10-26 (owner-commissioned)

**Author**: strategist session (baton `degrees-strategist`). **Commission**: the owner
reviewed the four published degrees and found the learner experience broken; this
document is the in-depth audit and the instruction set for the repair agents.
**Scope audited**: the `fcAcademyData` block and renderer in `site/assets/app.js`, read
against the module design files under `docs/degrees/modules/` and the integration
receipts. **Evidence status**: repository-data findings, cross-checked where stated;
the live site (clemvillatte.github.io) was additionally rendered and click-checked
for Daoism on 2026-10-26 — findings marked **[rendered-confirmed]** were observed
on the live pages; the remaining rendered pass (all four degrees, desktop + mobile)
is Phase E below.
**Companion guardrail**: `scripts/tests/degrees_learner_audit.py` (committed with this
audit; mechanically detects the defect classes below — see its known limits in
"Guardrails").

## Verdict

The published learner experience is broken in ways the owner correctly identified, and
every traced defect sits in the **integration and UI layers** (the app.js data block and
renderer), not in the pipeline's module-QC results. However, this audit does NOT
establish that the module designs are complete for their approved scope — a coverage
audit (Phase 0 below) is owed before anyone declares the curriculum itself sound. The
repair work is bounded and does not require rewriting module files; whether the
curriculum needs additions is a separate, currently-open question.

## Confirmed findings (repository-data evidence)

### A. The Daoism "Why This Text Matters" triple-listing — confirmed, with the design intent now traced

`DAO-M1-03` (Ziporyn, *Why This Text Matters: Daodejing*, 0:53:36) is required
full-length media in m1, m2 and m3, plus optional in m1 — four listings. **[rendered-
confirmed]**: the live Module II page lists the full "0:53:36" video with no segment
information. The module files
assign it precisely: m2 **revisits the same segments as m1** (21:34 of segments,
explicitly labelled a revisit: "if you completed m1 recently you may rewatch only the
segments you want to revisit"), and m3 assigns a **different 5:22 window**
(0:38:17–0:43:39) that discusses Zhuangzi's shoe-fits line. So the underlying design is
sound; the published representation loses all of it: no segment boundaries, no revisit
label, and a full 53:36 viewing implied three times. This is a schema and renderer
failure, not a curriculum error — but it is exactly what the owner saw.

### B. Lost and mislabeled assignments — confirmed

- **Pragmatism m3 is titled "Truth and the Will to Believe" but its core texts are
  missing from the data block**: James, *The Will to Believe* (Wikisource, public domain)
  and the assigned *Pragmatism* Lecture II and VI passages — all assigned in the module
  file (Reading A/B1/B2/B3, with measured word counts) — are absent from the sources
  array. The learner gets one Misak lecture. This is an integration-fidelity failure
  (readings need no segment support; they were simply not carried over), caught by
  nobody because no check diffs the data block against the module files.
- **`PD-M7-10`** ("Heidbreder, consciousness review article", required in psychdim m7):
  its assignment/provenance is **not yet traced** — it appears in
  `scripts/integrations/deg-psychdim-attach.py` and the integration receipt, but not in
  the m7 module file or the degree ledger under any of the names searched. Repair: search
  the exact PDF URL and identifier across module files, ledgers and git history, and open
  the PDF to verify what it actually is. If no approved assignment exists, remove it
  from required coursework with the evidence recorded. (A mislabeled source and an
  unapproved addition are different failures — establish which it is.)
- **Psychdim cross-module reuse** (Bloom lecture 7 in m3 and m4; lecture 4 in m3 and m7;
  Bouton in m3 and m7; the m8 capstone re-listing nine papers from m1–m7): the module
  files assign **different windows** of the same sources (e.g. m4 assigns lecture 7 at
  47:26–54:53), so these are designed segmented reuses — published as indistinguishable
  full duplicates. Same defect class as A.

### C. Empty-seeming capstones and missing connective tissue — confirmed

- `mod-bud-8` (12h) and `mod-prag-5` (5.25h) have zero required and zero optional
  media. The module files are explicit: "no new sources; the capstone draws on the prior
  modules' materials" — intentional. The defect is that the renderer shows an empty
  syllabus with no explanation, so a 12-hour module looks broken. `mod-dao-5` carries
  one text only.
- All four degrees: `wiki_readings: []` on every module (the wiki — this project's core
  asset — is not connected to the Academy), and an empty `openingNote` (the degree
  page's aside is blank). Whether every module must link the wiki is an owner/scope
  decision (finite-scope rule) — flagged as an opportunity, not mandated by this audit.

### D. Verbatim required/optional duplication — confirmed

`mod-dao-1` lists DAO-M1-01/02/03 as required **and** optional; `mod-dao-4` does the same
for DAO-M4-01; `mod-prag-1` for both Peirce essays. The module files mean "the
*unassigned remainder* of these items is optional further viewing" — again unrepresentable
without segments, so the learner sees the identical row twice.

### E. Internal codes leaking into learner-facing text — confirmed

- Buddhism titles carry band prefixes ("b1: Ethics First…", "b9 (elective): …");
  pragmatism titles are raw filenames ("m1-orientation: What Pragmatism Is",
  "m3-truth-and-the-will-to-believe: …" — the exact string the owner flagged).
- **[rendered-confirmed]** The Daoism Module II page shows the description as the
  internal level code ("L2 Guided application. Prerequisites: the exit criteria of
  m1…") and lists its prerequisite as the raw internal id "mod-dao-1" — the
  prerequisites field carries module ids that the renderer prints verbatim.
- Psychdim descriptions are internal level codes ("L1 - Use the framework…",
  "L2 Guided application. Prerequisites: …"); psychdim titles are bare dimension names
  ("Affective", "Cognitive").
- Assigned-window information is crammed into source *titles* ("assigned windows
  03:29-09:21…"); 8 of the 41 videos used by the four degrees have no `duration` field
  (49 text sources also lack durations — for readings, the right backfill is a
  word-count/reading-time label, not a running time; see Phase D).

### F. Renderer gaps (site/assets/app.js)

- `MOD_PROMPTS` (the "Reflect as you go" card) is hardcoded to legacy module IDs only —
  none of the new modules get one. **[rendered-confirmed]**: the Daoism Module II page
  shows no reflection prompt.
- Playback and progress ignore assignments entirely: the YouTube embed is built without
  the assigned start/end parameters, and "Mark as watched" stores completion **globally
  per source_id** — so completing one segment of a source marks every later use of that
  source complete across all modules. A displayed segment label alone will not fix this;
  completion must become per (module, source, assignment).
- The media row shows title/host/duration only; no week/step structure; no capstone
  "draws on prior modules" branch.

## Root causes

1. **Schema gap — no assignment object.** Module files assign precise windows and
   passages; the data model has only `source_id` + `level`, so integrators either
   repeated full videos (findings A, B-psychdim, D) or dropped readings they could not
   place (finding B-pragmatism). 
2. **Integration fidelity is undiffed.** Nothing requires the integrated media list to
   be diffed against the module file's assigned-media table; the pragmatism omission and
   the PD-M7-10 question would both have been caught.
3. **No learner-facing text rules.** Band filenames and level codes were copied verbatim
   because no rule forbade it.
4. **No learner-view QA gate.** Every existing check validates references and syntax;
   none asks "what does a learner see". The publication flip shipped these defects with
   all technical gates green.

## Repair plan — ordered phases

Run `python3 scripts/tests/degrees_learner_audit.py` after every phase (it must trend to
zero FAILs for the four degrees; its known limits are listed under Guardrails). Never
hand-edit the minified data line with find/replace — use the safe-splice recipe
(raw_decode boundaries) per INTEGRATION.md. **Coordination rule: one authorized
integration writer owns `site/assets/app.js` at a time** (the deg-fix-schema lane);
content and text lanes deliver per-degree manifests (see Phase 0) rather than editing
the shared file concurrently. Preserve the owner's degree order (psychdim, daoism,
buddhism, pragmatism) unless the owner supersedes it.

### Phase 0 — curriculum coverage matrix (owed before any "content is complete" claim)

For each degree, build `docs/degrees/integration/<degree>-manifest.json`: the module
files' assigned-media tables transcribed as data — per module: every assigned source
(URL or identifier, assigned windows/passages, role: teach/revisit/retrieval, word counts
where printed). Then produce the coverage matrix:
**approved competency/topic → module → assigned evidence in the design → published
assignment → covered / missing / intentionally excluded / unresolved**, distinguishing
(a) content present in the design but lost in integration, (b) content absent from the
design despite the approved scope (assess against opened academic sources; topical
relevance alone does not qualify — finite-scope rule), and (c) deliberately
out-of-scope material. This manifest then becomes the machine-checkable contract for
integration fidelity (see Guardrails) and the basis for the owner's redesign decision.

### Phase A — assignment schema + renderer (dissolves the duplication class)

1. Add an **assignment object** to each media reference: the module reference carries
   `segments` (for AV: `[{"start":"00:38:17","end":"00:43:39"}]`) or a reading locator
   (`locator`: chapter/section/word-count passage), an instructional `role`
   (teach / revisit / retrieval / capstone-return), and provenance to the module file
   revision. Global source records keep intrinsic identity only (canonical URL, media
   type, full duration).
2. Backfill values **from the module files / Phase 0 manifests** — e.g. daoism m2
   revisits m1's segments (windows printed in the m2 file), m3 assigns 0:38:17–0:43:39;
   psychdim m4 assigns lecture 7 at 47:26–54:53. Do not manufacture intervals from
   printed totals (21:34 is m2's total, not a window).
3. Renderer: print the assignment ("Watch 21:34 of segments" / "Read Reading A, 2,532
   words"), label revisits as revisits, and pass the assignment — not just the source —
   into playback (`start`/`end` embed parameters) and into completion (per
   module+assignment, not global source_id).
4. Validation: `node --check`, `node scripts/tests/academy-display.test.cjs`,
   `python3 scripts/tests/test_academy_migration.py`, this audit script, and the
   Playwright suites where the environment allows.

### Phase B — title and description hygiene (mechanical)

1. Strip band codes/filenames from titles ("m1-orientation: What Pragmatism Is" →
   "What Pragmatism Is"; "b1: Ethics First…" → "Ethics First — Orientation to the
   Buddhist Walk"), with an old→new receipt.
2. Rewrite descriptions as 1–3 sentences of learner prose from each module file's
   "What this module is for" section (humanizer rules apply). No L-codes; prerequisites
   belong in the prerequisites field — and the renderer must print prerequisite
   *titles* ("Module I — Entering the Daoist Walk"), never raw module ids.
3. Give psychdim modules real titles (dimension name may remain as a kicker).

### Phase C — content completion (only what the manifests establish)

1. Pragmatism m3: add the missing James and Pragmatism-lecture sources from the module
   file's verified list (this one is already established — no matrix needed).
2. PD-M7-10: trace or remove per finding B, evidence recorded.
3. Capstones: add a `drawsOnPriorModules` note (data field + renderer branch) so
   b8/m5/daoism-m5 render an explicit "this capstone returns to the materials of
   modules I–IV" instead of an empty syllabus; the audit script treats that flag as a
   valid empty-media state.
4. openingNotes (2–4 sentences per degree, centered on the Walk-of-Life value
   proposition) and MOD_PROMPTS for the new modules (drawn from each module's
   question) — or move prompts into the data block.
5. wiki_readings: present the option to the owner with a per-module candidate list from
   the Phase 0 matrix; do not mass-link without the finite-scope check.

### Phase D — duration and label backfill

Backfill `duration` for the 8 videos missing it from the verification receipts; move
assigned-window text out of titles into `segments`; for text sources backfill reading
locators and word-count-based reading time (never a fabricated running time).

### Phase E — rendered learner pass and close-out

1. Serve the site, open each of the four degrees in a real browser (desktop + mobile),
   and click through every module as a learner: find where to begin, understand the
   exact assignment, open its passage, complete an activity, move to the next module.
   Record reproducible problems and screenshots per degree (this session's findings are
   repository-data findings; this pass is what converts them into confirmed UI
   observations).
2. Run the audit script to zero FAILs on the four degrees. The deg-qigong flag it
   raises is a pre-existing practicum item — the supervisor triages it separately.
3. Re-run whole-degree QC, record receipts, update INTEGRATION.md with the guardrails
   below.

## Guardrails — so this cannot happen again

1. **`scripts/tests/degrees_learner_audit.py` becomes a publication gate** once its
   fixtures pass (see 3): no degree may flip to (or remain at) `status: "complete"`
   with FAILs on it. Known limits today: it checks the data block, not the rendered
   pages; it cannot detect an *omitted* source (no dangling reference is left) — the
   Phase 0 manifest closes that hole (extend it to diff manifests against integrated
   media lists); alias detection (same recording under two source_ids) currently keys
   on canonical URL + YouTube id; segment values are format-checked but not
   range-validated against the source's full duration — do that during Phase A.
2. **Learner-facing text rules** (add to INTEGRATION.md): titles never contain band
   codes or filenames; descriptions are prose, never level codes; assigned windows live
   in `segments`, never in titles; a source may appear in several modules only as a
   distinct assignment (role + segments/locator).
3. **Fixtures for the checker**: legitimate segmented reuse, an explicit revisit,
   a retrieval reuse, a valid `drawsOnPriorModules` capstone, a duplicate recording
   under different ids, an omitted required reading (via manifest), an invalid time
   range, a leaked filename — valid cases must pass, invalid cases must fail, before
   the gate is binding.
4. **Diff-the-docs rule**: every integrated module's media list must be diffed against
   its Phase 0 manifest, with the diff attached to the integration receipt.
5. **Learner-view pass before any publication flip**: the person flipping `status`
   (or the supervisor post-reviewing) renders the degree and clicks through all modules
   before signing. Machine checks alone are insufficient — that is this audit's lesson.
6. **One writer per shared file**: app.js data+renderer edits go through the single
   integration-writer lane; other lanes deliver manifests and markdown.

## Lane routing for the repair wave (suggested)

- `deg-fix-schema` (Phase A + checker hardening): one agent, owns app.js, do first.
- `deg-fix-text` (Phases B + D): per degree, after A, from manifests.
- `deg-fix-content` (Phases 0 + C): per degree, pragmatism first (established missing
  content); produces the manifests that A and B consume — run it in parallel with A if
  manifests are delivered module-by-module, else after A.
- Supervisor: fold the audit script + learner pass into the publication protocol;
  triage the deg-qigong flag; present the wiki_readings option to the owner.
