# Mobile Responsiveness — Handoff

## What this is
The site (https://clemvillatte.github.io/flourishing-compendium/) works on desktop but is unusable on phones (tested: iPhone 16e, Chrome). The user (non-technical writer, the site's owner) asked for a careful mobile pass: Randomiser super-minimal, Library actually usable, Graph with collapsible panels and a collapsible node card, etc.

## Repo & deploy essentials
- Repo: /home/user/workspace/repo — clone of Clemvillatte/flourishing-compendium, branch main. `gh` CLI and git push are pre-configured (push goes through git-agent-proxy).
- Source of truth: content/*.md → scripts/build.py → site/data/wikiData.json.gz (gitignored; GitHub Actions "Build and deploy to Pages" builds it on every push, ~25-30s).
- Live check: `gh run list --repo Clemvillatte/flourishing-compendium --limit 1`, then `curl -s -o /tmp/f.js "https://clemvillatte.github.io/flourishing-compendium/assets/<file>.js?nocache=$(date +%s)" && md5sum /tmp/f.js site/assets/<file>` (must match).
- CACHE-BUSTING (learned the hard way): index.html pins THREE assets directly with `?v=` (style.css, boot.js, editor2.js) AND defines the master version inline: `<script>window.FC_VER = '20261018e';</script>` (~line 297). boot.js appends `?v=FC_VER` to app.js/extras.js/graph.js AND the three data/*.json.gz datasets. BUMP FC_VER (and the three ?v= strings) ON EVERY DEPLOY or browsers keep serving stale JS. The GitHub Actions build may do this — verify before pushing manually.
- The user actively edits the site (editor writes commits directly to main). ALWAYS `git fetch origin && git rebase origin/main` before pushing; pushes get rejected otherwise.
- Git identity is configured locally. Never use or echo the user's GitHub token (it was once exposed in a screenshot; they were advised to regenerate it). QA in the browser must stub `window.fetch` (intercept api.github.com, return canned md, record PUTs) and set a dummy token `localStorage.setItem('fcgh_token','qa-dummy')` — never make real writes from QA.

## Mobile design decisions (agreed with the user)
1. **Global**: iOS 100vh bug → use 100dvh with fallback; bottom tab bar for view switching on phones; larger touch targets (min 44px); hide decorative text.
2. **Randomiser**: super minimal — hide the filter bar behind a "Filters" toggle; compact header; card + Next button dominate.
3. **Library**: read-first. The search/list column becomes a slide-over sheet opened from a floating "Browse" button; tree column hidden. Entry meta buttons wrap and stay tappable.
4. **Graph**: controls (.graph-top) hidden behind a floating menu button (☰); drawer becomes a bottom sheet with two states — collapsed (title + connection count peeking at the bottom edge) and expanded (tap to open). Legend + hint hidden on phones. The canvas gets the full screen.
5. **Editor**: full-screen overlay below ~600px.

## Round 4 (user feedback: graph STILL unusable on mobile) — DONE, deployed, QA-verified
The user reported that selecting/deselecting/switching nodes still caused a chaotic animated reorganisation with heavy lag — "the animation of all the nodes makes it impossible". All changes in graph.js + one in the touch handler:
1. **Phones snap, desktop glides**: `spreadSnap` flag (same ≤920px media query + change listener as spreadNoRoom, ~line 515). In `applySpread`, `k = spreadSnap ? 1 : 1-exp(-5*dt)` — belt targets apply in ONE pass; `spreadAnimating` is never set on phones, so the render loop stops right after the snap frame. Selecting, deselecting or switching is a single (heavier) frame, then the canvas is fully static.
2. **The spread is a STATIC view-layer state on phones** (critical — first attempt failed QA): `snapState` invalidation key in applySpread. Once snapped, later passes EARLY-RETURN until something actually changes (new spreadSlots from setSpread, the center's base x/y moved by a drag, size-slider/kind-toggle rebuilds). Without this, k=1 re-applied the exact targets every frame, wiping the separation nudges → endless apply→separate→reset loop at 4 separation passes/frame while the loop was awake (panning, camera glide). With it: exactly 1 separation pass per frame while awake (verified), and the extra 3 passes run only on the actual snap frame (gated on `spreadJumped`, consumed by the frame loop).
3. **Context nodes truly never move on phones**: the belt-mode context push (beyond geo.ctxR) is now guarded by `!spreadNoRoom` (the round-3 fix only guarded the NON-belt fallback branch — belt mode is the default, so phones still displaced everything within 850px). Also `separateDisplayed` on phones: nodes outside the selection's neighbourhood are immovable (belt members get the full push; context–context overlaps in the frozen base layout are left alone — also with no selection, so the deselect pass doesn't nudge them). Verified: selecting PP046 (97-node belt) moves EXACTLY 97 nodes, 2391 context nodes pixel-identical; deselect returns to 0 moved.
4. **Tap-select fits the belts on phones**: `select(n)` calls `fitToBelts()` when `spreadSnap` (on a 390px viewport a belt around the tapped node is routinely half off-screen). Desktop keeps no-auto-travel. Deselect never moves the camera.
5. **N+2 off by default on phones** (load-time): `if (matchMedia('(max-width:920px)').matches) phys.nb2 = false` — the user called the far belt "unperceivable" and asked for "N+1 or (N+1 > N+2)"; fitting a 96-node Z belt zooms out to ~0.05 (dots). With N+1-only, focus lands at a readable ~0.45. Toggle still in the physics panel; the panel's RESET re-applies the phone default (`if (spreadSnap) phys.nb2 = false`). Desktop unchanged.
6. **Touch parity fix**: tapping empty canvas on touch now deselects (the touchend handler lacked the mouse path's `select(null)` — previously impossible to deselect by tapping the map on a phone).
- QA hooks added: `window.__physDebug()` (live physics settings), `sepCalls` counter in `__graphDebug()` (separation passes run).
- Verified in a preview deploy (pattern below): desktop easing intact (offsets animate 0→1565→2244→2294, z-belt 96, running during); phone: tap-select = one frame (97 moved, loop stopped), tap-switch = one frame, tap-empty deselect = one frame to 0 moved; camera fits on tap (zoom 0.465 with N+1-only, A001); pan with selection = exactly 1 separation pass/frame; phone-width load → nb2:false, desktop-width load → nb2:true; no horizontal overflow at 390px; drawer bottom sheet intact.

### Round 4 QA pattern (preview deploy — how to test local changes in the cloud browser)
The old cloud QA loaded the live site, which can't test local changes, and the sandbox browser transport is unavailable. Working pattern:
1. `python3 scripts/build.py` (repo root) regenerates site/data/*.json.gz (gitignored).
2. `deploy_website` on `site/` with `should_validate: false` (validation blocks on localStorage, which is all try/catch-guarded in the app — safe). Navigate the cloud browser to the returned internal_url.
3. **Bump `FC_VER` + the three `?v=` strings in index.html BEFORE EVERY redeploy** — the browser serves stale JS otherwise (symptom: new QA hooks like `__physDebug` undefined; this bit round 4 twice). The GitHub Actions build stamps FC_VER with the commit SHA automatically for the live site, but PREVIEW deploys serve the repo's manual value.
4. Arrange at DESKTOP metrics (default viewport): `tabGraph`.click() → wait for #graphArranging visible → `window.__qaFinishWarmup()` (the eval may time out — the sync warmup keeps running in-page; poll `__graphDebug().warmTicks === 0` after ~30-60s). Phone-emulated warmup can CRASH the tab — never finish warmup under phone metrics.
5. Then `Emulation.setDeviceMetricsOverride {width:390,height:844,deviceScaleFactor:3,mobile:true}` — spreadSnap/spreadNoRoom flip live via the matchMedia listener. Drive selection with synthetic TOUCH events (TouchEvent touchstart/touchend on #graphCanvas — the touch path is what a phone uses; touchend needs `touches: []`). Find an empty canvas spot by dispatching mousemove and reading `canvas.style.cursor !== 'pointer'`.
6. Phone-only load defaults (like nb2) must be verified with a fresh page load WHILE the device override is active.
7. NOTE: /home/user/workspace/fc-test (jsdom suite) is NOT present in a fresh sandbox; it only covers editor2.js, which this round didn't touch.

## Round 7 (back button + desktop perf) — DONE, deployed
1. **Back-to-previous-node button (←)**: selHistory stack in graph.js. select(n, opts) records the node being LEFT on every distinct transition (including DESELECT — the accidental-tap case: deselect then back restores). Back-nav pops, skips stale/invisible/duplicate entries, and re-selects without re-recording. Offscreen restores glide the camera (centerOn — camera-RELATIVE screen math, works on phones too via the belt fit inside); on-screen restores don't move the camera. Two buttons: #graphBackBtn in the desktop control bar (beside Layout settings), #graphBackBtnM beside the ☰ button on mobile; CSS-switched at the 920px breakpoint; disabled when no usable history (refreshed from select(), applyToggles(), and when back-nav exhausts a stale stack). SEL_HIST_MAX 60.
2. **Desktop perf — root cause found by profiling (prof counters in __graphDebug().prof)**: the render loop NEVER went idle after a selection. applySpread (belt-target easing) and separateDisplayed (overlap separation) fought forever — separation pushed nodes off their belt targets, the easing pulled them back, spreadAnimating never cleared → endless rAF (~30fps, 33ms median frames) until the next interaction. Fix: separation nudges now also adjust the easing TARGET (per-node sepAx/sepAy accumulators, folded into tx/ty in applySpread, cleared for all nodes in setSpread), so its fixes are permanent and both passes agree. Selections now settle in ~2s and the loop stops; idle = zero CPU. Loop-stop condition extended with sepMoved (separation quiet too), with a 0.5px tolerance — pair distances converge asymptotically, so "any movement" would keep the loop alive forever (Zeno trap found in QA: loop ran 12s+ with maxErr=0, maxPush≈0).
3. **Separation/declutter hot-loop optimization**: integer grid keys ((gx+4096)*8192+(gy+4096)) and vis-index pair ordering (n._i) instead of string concat + String(id) compares. Measured separation cost 40.4→10.2→8.9ms/frame in the QA browser (hottest code on the frame loop). Frame median 33.3→16.7ms in QA emulation; render was never the bottleneck (~3ms).
4. **Verified**: zero position drift on wake after pan (with selection, after deselect, post-drag — 2488 nodes hold exact positions); phone snap (0ms settle), labels, empty-tap deselect, back button all intact on 390×844; desktop belt rendering + drawer verified at readable zoom. Known behavior change: after deselect, nodes rest at slightly decluttered positions (max ~60-90 world units off base) — stable, consistent, no accumulation across cycles (setSpread clears accumulators).
